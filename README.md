# FLARE

**Fast Learned Approximant & Reduced-order Emulator** — a neural-network surrogate
for gravitational waveforms. FLARE learns the amplitude and phase of a time-domain
waveform approximant (SEOBNRv4, SEOBNRv4HM, IMRPhenomD) and reproduces it two orders
of magnitude faster, at parameter-estimation-grade accuracy.

FLARE is also a **workspace for automated discovery of model architectures**: a
FastAPI dashboard and an autonomous agent that proposes surrogate designs, trains and
evaluates them, reads the leaderboard, and iterates — steering the search toward higher
waveform match without a human in the loop.

This repository contains the **training, inference, and search code** so the models and
results can be reproduced from scratch. It does **not** ship trained weights, cached
datasets, or benchmark outputs — everything is regenerated by the commands below.

## What's here

- A two-stage surrogate: an MSE warm-up followed by fine-tuning directly on the
  waveform **match**, which is what carries the model into the PE-grade regime.
- A reduced-order (SVD/POD) representation with per-mode amplitude/phase networks.
- A higher-mode model (`SEOBNRv4HM`) that learns five aligned-spin harmonics and
  recombines them through spin-weighted spherical harmonics.
- Matched-filter parameter estimation against real GWOSC events (`emcee` or
  `dynesty`), using the surrogate as the fast template engine.
- An **automated architecture-search workspace**: a web dashboard (FastAPI + React)
  and an autonomous agent that proposes → trains → evaluates → ranks model designs,
  driven by a local GGUF model, the Claude API, or random search.

## Installation

Prerequisites: Python ≥ 3.9, and the system libraries PyCBC/LALSuite require.
A CUDA GPU is optional — everything runs on CPU (the smoke test below is CPU-only).

```bash
git clone https://github.com/Zeos-ctrl/FLARE.git
cd FLARE

python -m venv .venv
source .venv/bin/activate

# Core training + inference
pip install -e .

# Optional: parameter-estimation extras (GWOSC, emcee, dynesty, corner, ...)
pip install -e ".[estimator]"

# Optional: dashboard backend + autonomous architecture search
pip install -e ".[api]"        # FastAPI dashboard
pip install -e ".[agent]"      # Claude-driven proposer (local-GGUF / random need no extras)

# Optional: dev tools (pytest, black, flake8, ...)
pip install -e ".[dev]"

# ...or everything at once
pip install -e ".[all]"
```

For GPU training, install a CUDA build of PyTorch from <https://pytorch.org/> before
`pip install -e .`.

## Quick start

### 1. Reproduce the pipeline end-to-end (CPU, ~2 minutes)

```bash
python scripts/smoke_test.py
```

This trains a tiny model on a handful of freshly generated SEOBNRv4 waveforms,
loads the resulting checkpoint, predicts a waveform, and checks the output — a fast
proof that data generation, training, and inference all work on your machine. It
writes to `checkpoints/smoke_test/` (git-ignored).

### 2. Train a real model

```bash
# Dominant-mode SEOBNRv4 surrogate
python -m src.cli train --project seobnrv4 --samples 20000 --waveform SEOBNRv4 --device cuda

# Smaller CPU run
python -m src.cli train --project seobnrv4_small --samples 2000 --epochs 200 --device cpu
```

Checkpoints (weights, reduced bases, config, normalisation) land in
`checkpoints/<project>/`.

### 3. Hyperparameter search / train together

```bash
python -m src.cli tune  --project tuned --hpo-trials 50 --hpo-samples 2000
python -m src.cli both  --project tuned --hpo-trials 50 --samples 20000   # tune, then train
```

### 4. Parameter estimation on a real event

Requires the `estimator` extra. Uses the trained surrogate as the template engine
inside a matched-filter likelihood:

```bash
python -m src.cli estimate \
    --project seobnrv4 \
    --event GW150914 \
    --detectors H1 L1 \
    --nwalkers 32 --nsteps 2000 --bank-size 2000
```

Outputs land in `checkpoints/<project>/estimation/<event>/`
(`posterior_summary.json`, `corner.png`, and a time-domain reconstruction diagnostic).

> **Matched-filter PE needs fixed-window models.** Match-optimised surrogates emit
> merger-aligned, duration-normalised waveforms that are not usable for matched
> filtering against real detector data. Train with `td_fixed_window=True` (a full
> waveform on a fixed 4 s / 4096 Hz physical grid, merger at `merger_frac·L`, no
> trim); the estimator detects this from the checkpoint and applies the standard
> pycbc conditioning recipe automatically.

## Using a trained model

```python
from src.inference.predictor import WaveformPredictor

predictor = WaveformPredictor("checkpoints/seobnrv4", device="cuda")

h_plus, h_cross = predictor.predict(
    m1=35, m2=30,      # solar masses
    s1z=0.1, s2z=-0.2, # aligned spins
    inc=0.5,           # inclination (rad)
)
strain = h_plus.data
```

The higher-mode model is loaded through `src.inference.surrogate.load_surrogate`,
which exposes the same `predict(m1, m2, s1z, s2z, inc)` interface.

## Reproducing the benchmarks

The `scripts/` directory holds the campaign drivers used to produce the paper
results (each writes its own output directory, all git-ignored):

| Script | What it does |
| ------ | ------------ |
| `scripts/build_bank.py`      | Generate a training bank of waveforms |
| `scripts/pe_benchmark.py`    | 13-event PE benchmark, surrogate vs live pycbc (`--sampler nested` for dynesty) |
| `scripts/pe_compare.py`      | Per-event posterior comparison / corner overlays |
| `scripts/hm_pe_catalogue.py` | Higher-mode coherent-injection catalogue |
| `scripts/hm_pe_event.py`     | Higher-mode PE on a real event (e.g. GW190412) |

## Automated discovery of model architectures

FLARE ships a workspace for searching the surrogate design space automatically. The
unit of search is an **experiment**: a durable, repeatable train→eval run that records
one comparable score, `mean_match` (0–1, higher is better). Experiments are stored under
`experiments/`, run one at a time through a background job manager, and ranked on a
leaderboard.

On top of experiments sits an **auto-run**: an autonomous loop that reads the
leaderboard, proposes the next design, submits it, waits for the result, and repeats —
steering toward higher match. What to try next is delegated to a pluggable **proposer**:

| Proposer | What it uses | Setup |
| -------- | ------------ | ----- |
| `random` | Uniform sampling of the search space | Nothing — always available |
| `local`  | A local GGUF model on an OpenAI-compatible server (llama.cpp / LM Studio / Ollama) | Run the server; no Python extra |
| `claude` | The Claude API | `pip install -e ".[agent]"` + `ANTHROPIC_API_KEY` |

If `local` or `claude` is selected but unavailable, the loop falls back to `random`, so
it never stalls. The control surface is documented in `agent/AGENT.md`, and
`agent/search_example.py` is a runnable random-search reference:

```python
from src.agent.client import FlareClient
client = FlareClient("http://localhost:8420")

for _ in range(budget):
    board = client.leaderboard(group="sweep-1")          # best designs so far
    spec  = propose_next(board, client.search_space())   # your logic / an LLM
    rec   = client.wait(client.submit_experiment(spec)["id"])
    print(rec["name"], rec["metrics"].get("mean_match"))
```

## Dashboard

An optional web dashboard (FastAPI backend + minimal React/Vite frontend) drives the
whole workspace through a GUI: edit configs, preview datasets, launch and monitor
training/tuning/evaluation, run GWOSC parameter estimation, and start/watch the
autonomous architecture search — with live progress over Server-Sent Events.

```bash
# 1. Backend
pip install -e ".[api,estimator]"
flare-api                        # http://localhost:8420  (health: /api/health)

# 2. Frontend (separate shell)
cd frontend
npm install
npm run dev                      # http://localhost:5173, proxies /api to :8420
```

The backend (`src/api/`) is a single-process job manager intended for one research user,
not a distributed task queue.

## Configuration

Defaults live in `config.yaml` (waveform settings, network architecture, training
hyperparameters) and are overridden per run by the CLI flags above.

```

├── config.yaml            # Waveform / model / training defaults
├── pyproject.toml         # Package + optional-dependency groups
├── src/
│   ├── cli.py             # train / tune / both / estimate

│   ├── data/              # waveform generation, features, reduced basis
│   ├── models/            # MLP / ROM amplitude & phase networks, factory
│   ├── inference/         # predictor, higher-mode surrogate, estimator, GWOSC
│   ├── api/               # FastAPI dashboard backend + job manager + auto-run
│   ├── agent/             # search-space client + proposers (random/local/claude)
│   └── utils/             # metrics (match), I/O, uncertainty
├── agent/                 # auto-run control surface (AGENT.md) + example searcher
├── frontend/              # React (Vite) dashboard UI
├── scripts/               # training-bank + PE benchmark drivers + smoke_test.py
└── tests/                 # unit tests (pytest)
```
